# 06 | Decision, repair and pivot

Shared rules: [EXECUTION_POLICY](../../docs/EXECUTION_POLICY.md), especially the **manuscript writing lock**. Read original Run receipts before interpreting summaries; `PAPER_OPPORTUNITY=YES` never authorizes a paper outline or draft.

- Distinguish INVALID (broken protocol/leakage), INCONCLUSIVE (insufficient evidence), real negative at mechanism level, Task infeasibility and Claim novelty failure.
- **Scope-specific cause map:** ENGINEERING_ERROR → repair affected code/data/evaluator; SIGNAL_LIMITATION → inspect predecision legal information and Task; MECHANISM_FAILURE → HOLD challenger while preserving verified simple reference; NOVELTY_FAILURE → revisit independent scientific gap (PD-RW if applicable); CONFIRMATION_FAILURE → narrow Claim or plan new independent evidence. These are reasoning labels, not new CLI enum values. Do not treat a simple method's valid success as proof of paper novelty or a complex model's loss as proof the entire data area is unusable. Retain valid old evidence; do not elevate model-score improvement into scientific novelty.
- **Do not misclassify incremental novelty:** a fair simple reference matching the challenger is a negative result for that mechanism, but may still support a new efficiency, calibration-cost or boundary Claim. If one modest, specific and reproducible contribution survives nearest-work comparison, route to the minimum paper-evidence path rather than require larger model gains. If it only reproduces known results, retain the engineering asset without implying a paper.
- **Narrow scientific-claim rescue before stopping a valid branch:** if a hard mechanism fails but reliable baseline/residuals expose a reproducible, previously unanswered *narrow* effect or real label/compute-cost advantage, route that as `PAPER_CANDIDATE_WITH_GAPS` (narrative shorthand, **not** a CLI/event value) and name the single cheapest decisive test. A small result can warrant scientific follow-up, but Q2+ suitability remains a separate evidence/venue question; lack of global SOTA or a new backbone is not STOP. If the finding is a post-hoc slice, merely known or not identifiable from legal information, preserve it as exploratory/engineering rather than claiming publication readiness. Do not repeat novelty review without new evidence.
- **Mandatory judgment at a decision boundary, not a new process gate:** for a valid `RUN_RESULT`, `NO_GAIN`, or `TASK_BLOCKED` before proposing model escalation/HOLD/PIVOT, answer `PAPER_OPPORTUNITY: YES | UNKNOWN | NO` with evidence and an attainable narrow Claim **and** a separate `Q2_COMPETITIVENESS` assessment (not inferred from the small claim). If YES, compare Q2-relevant scientific evidence completion cost with more algorithm search and prefer evidence-gap closure; if UNKNOWN, nominate one affordable discriminatory check; if NO, preserve valuable assets and make the branch-scoped decision. No repeated venue queries on unchanged evidence, no fabricated journal acceptance odds and no holdout access without approval. Handoff to PD-RW with `ONE_CLAIM | CORE_RUN | NEAREST_GAP | CRITICAL_MISSING_TEST | NEXT`.
- **Project success vs branch failure:** a promising small paper/valid baseline is not by itself Q2+ project success. Report `Q2_POTENTIAL_SUPPORTED/Q2_UPGRADE_POSSIBLE/Q2_UNCERTAIN/BELOW_Q2_TARGET` only as evidence-backed scientific judgment against real Q1/Q2 analogs (Q1 preferred), per [Execution Policy](../../docs/EXECUTION_POLICY.md). Absence of evidence is UNKNOWN, not automatic failure; model-level negative and project-level goal failure are distinct. No acceptance is required for research success.
- **Harvest before expensive escalation/HOLD/STOP:** inspect whether valid Runs and negatives contain overlooked scientific knowledge, not just the first profitable result. Use [SCIENCE_RESULT_HARVEST.md](../../docs/SCIENCE_RESULT_HARVEST.md) to distinguish `ARTICULATION_GAP` (evidence sufficient but research Claim mapping weak), `EVIDENCE_GAP` (key control/confirmation missing), `BOTH`, and `NONE`. Preserve source-linked exploratory candidates; project pivot and sealed access remain user-owned. Forge does not infer Q2 novelty from an attractive figure or cherry-picked group.
- **Post-algorithm audit routing:** for a stable credible Run with potential scientific value beyond DEV gains, use [POST_ALGORITHM_SCIENCE_AUDIT.md](../../docs/POST_ALGORITHM_SCIENCE_AUDIT.md) to recommend `UPGRADE_PILOT / EVIDENCE_ONLY / KEEP_ORIGINAL / UNKNOWN`; require named nearest-work gap, competing explanation, legitimate decisive experiment and cost. These are narrative judgments, NOT router events; do not auto-train or write a paper.
- Pick CONTINUE, REPAIR, NARROW, HOLD or real PIVOT according to the *new information obtainable per remaining cost*. One negative Pilot ≠ project STOP; repeated experiments with the same falsified premise and no discriminatory value should stop.
- Ordinary bugs: reproduce → root cause → targeted fix → verify, autonomously within authorized scope. For a **scientific** negative, don't invoke engineering-debug loops to inflate scores. Superpowers debugging Skill is an optional reference only.
- Task and protocol transitions require versioned `TASK_PIVOT` / `PROTOCOL_REVISED` decisions; old Champion is retired, negative history preserved. `core.cli recover` previews/repairs only a safe one-event interruption.

**Decision-owner handoff:** in-scope fix/probe with verified authorization → direct copy-ready next Agent instruction. Major Task pivot, project STOP, new budget/confirmation or uncertain permission → recommendation, benefits/risks and options only, **no execution prompt until user decides**. See [NEXT_ACTION_POLICY](../../docs/NEXT_ACTION_POLICY.md).

**Research-problem ownership:** use a source-bound [PD-RW science handoff](../../adapters/science_handoff.py) if available. Forge's `opportunity_review` cannot automatically rank research questions: without `--selected-hypothesis-id` it yields no chosen research problem. Once PD-RW/user selects the scientific question, recommend the cheapest decisive authorized next **experiment** for that question; if the selected scientific question or permission needs human decision, use [NEXT_ACTION_POLICY](../../docs/NEXT_ACTION_POLICY.md) and offer recommendation/options without an execution prompt. Do not claim the handoff hash verifies JCR Q2 or causal mechanisms.

**High-value scientific decision:** consult [HIGH_VALUE_RESEARCH_ENGINEERING](../../docs/HIGH_VALUE_RESEARCH_ENGINEERING.md) only when a new Task/Claim/expensive experiment is being selected. Distinguish low-cost easy DEV gains from new scientific knowledge that matters relative to original nearest work; first check whether data can separate alternative explanations. Route the most decision-changing authorized probe, not a model-size race. Missing Q2 originals/independent data means UNKNOWN, not project STOP. Retain user-owned decisions under [NEXT_ACTION_POLICY](../../docs/NEXT_ACTION_POLICY.md).

**Handoff:** failure_scope, cited new evidence, decision, smallest next probe, possible outcomes and any genuine permission blocker.

**APACE→SAFE-Gait failure lesson:** when a policy has theoretical Oracle room but consistently fails fixed/random controls, diagnose hidden-information/indistinguishable-action premises before changing network complexity. If a *realistically available* K-shot calibration observation changes the information condition, propose a distinct versioned Task, retain original negative evidence, recheck same-K baselines and independent confirmation eligibility. If no genuinely different information or mechanism exists, do not relabel a superficial pivot as progress. Case (optional): https://github.com/phr-devil/Problem-Data-Research-Workflow/blob/main/LESSONS/SAFE_GAIT_APACE.md.

**Failure triage with the v0.9 feasibility summary:** invalid labels/evaluator → repair affected evidence; undertraining/fairness deficit → bounded equal-budget anchor; candidate not better than matched simple reference → inspect residual structure, legal new information or genuinely different failure premise; heterogeneous positive DEV results → narrow only with new validation. Negative Pilot or UNKNOWN does **not** auto-STOP the project. Do not keep searching the same falsified lever without information gain.

**v0.10 science feedback:** For a real verified DEV result, `python -m adapters.hypothesis_bank feedback --project PROJECT --bank BANK.json --hypothesis-id H01 --run RUN.json --assessment INCONCLUSIVE --out BANK_v2.json` creates a new evidence-linked revision. Assessments are Agent interpretations, not machine-certified effects. On an invalid evaluator first repair the Run; on a plausible negative probe revise premise or fallback at the correct scope; on positive DEV gains still compare strong alternatives/nearest work and eligible independent confirmation.
