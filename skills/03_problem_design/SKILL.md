# 03 | Scientific problem design

Shared rules: [EXECUTION_POLICY](../../docs/EXECUTION_POLICY.md). Invoke when no adequate Task exists or the evidence supports a genuine change; a model-level failure first goes to 06.

- Separate observation, scientific question, baseline, hypothesized mechanism, potentially new contribution, strongest alternative and **what would falsify each**.
- Evaluate feasibility (truth, legal inputs, independent groups, quick baseline, resources) and science value (nearest-work delta, capability/insight). Unknown ≠ rejection. Keep one primary Task plus a genuinely different fallback **when useful**, not mandatory counts.
- Optional task tiers: L0 valid baseline → L1 feasible capability → L2 mechanism → L3 harder information setting; use what fits the data, not a compulsory ladder.
- `adapters.novelty_check` creates a **UNVERIFIED** prior-paper screening matrix, not proof of novelty. Read real originals before claiming independent contribution. Selected development data and selection history remain auditable.
- DRAFT Tasks allow uncertainty. ACTIVE needs actual protocol, group split, metric, legal_inputs, baseline and holdout policy.

**Handoff:** TaskSpec, minimal first falsification probe, reason for proposed mechanism and alternate route if its premise fails. Do not generate a manuscript plan before credible evidence.

**Information feasibility (trigger only when relevant):** An Oracle or perfect-action gain is **correctability**, not proof a policy can identify that action from information available before prediction. Check the legal label budget K (unit, acquisition time), support/query separation and same-K strong simple baseline. A K=0→K=1 shift is a new versioned Task/protocol/Claim, never success of the old K=0 goal. Cross-project case: https://github.com/phr-devil/Problem-Data-Research-Workflow/blob/main/LESSONS/SAFE_GAIT_APACE.md (read only on symptom).

**v0.9 cheap signal-headroom check (optional):** Do not choose a complex architecture on the assumption that an observed residual is recoverable. If trusted prior DEV Runs exist, ask what legitimate information the strongest simple method already used, which groups/conditions show remaining structure, and what *distinct falsifiable* mechanism/ability is left. UNKNOWN is not rejection; formal new Task requires a different scientific claim or legal information setting.
