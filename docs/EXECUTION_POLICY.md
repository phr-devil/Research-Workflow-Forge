# AI Research Execution Policy · v0.15

This file is the **single shared source** for execution efficiency. Read it once per research session; each Skill adds only its specific task. Requirements are defaults unless scientific correctness, actual permissions or the user's instruction require otherwise.

## Next-step user/Agent handoff (mandatory)

Follow [NEXT_ACTION_POLICY](NEXT_ACTION_POLICY.md). **Within verified authorization**, choose and emit a compact, immediately usable next-Agent instruction for autonomous technical work or a strongly justified in-scope option. **For human-owned decisions or missing permissions**, state the recommendation with reasons and 2–3 viable choices; do not output an Agent execution command until the user chooses. The user owns scope/pivot/project-STOP, new money/download/fit/compute/sealed/communication permissions, reviewed research summary and manuscript-writing authorization. This rule does not weaken the writing lock or turn a route into approval.

## Manuscript writing lock (highest-priority, no automatic unlock)

- **Default `WRITING_LOCKED`** for every project and agent session. First produce a research-results summary (task/protocol, verified and negative Runs, baselines, named prior-work gap, independent evidence, caveats, incomplete experiments). The user must **explicitly review/accept that summary**, then **separately and explicitly authorize writing** the named manuscript/project. Both decisions may occur in one clear user instruction after the summary exists, but neither can be inferred from silence or agent judgment.
- A credible Run, `DRAFTABLE`, `PAPER_PATH_CANDIDATE`, `CONFIRMED_CLAIM`, positive review, stage transition or stored approval flag **never** substitutes for verified original user messages. Questions such as “can we publish/write yet?” are *not* instructions to draft; “continue the project”, CPU/GPU/confirmation/submission permissions are not writing permissions. If either prerequisite/source is missing, or approval is revoked/out of scope, remain locked.
- **While locked:** permitted: experiments within actual research authorization, evidence tables, scientific claim maps, comparisons, diagnostic figures, missing-evidence plans, venue/impact assessments, and non-manuscript research summaries. **Prohibited:** generating or editing manuscript title/abstract, paper-style outline, introduction/method/results/discussion/conclusion prose, paper first drafts, publication-layout figures or submission manuscript files. Scientific methods/protocol notes and reproducible diagnostic plots are allowed when not disguised as manuscript text.
- Legacy `PAPER_COMPLETION_PRIORITY` / “submit-ready priority” means **`EVIDENCE_COMPLETION_PRIORITY`** before authorization: close only the scientific evidence gaps, do not create paper content. The writing lock is **not** an additional gate on authorized research, independent confirmation, or ordinary debugging.
- For cross-session handoff optionally retain human-readable pointers `RESEARCH_SUMMARY_REF`, `SUMMARY_USER_REVIEW=PENDING|REVIEWED`, `MANUSCRIPT_WRITE_AUTH=LOCKED|APPROVED` with originating user-message references and project/claim scope, **not** new CLI enums or self-issued permissions; verify the actual user text again before writing. If provenance cannot be checked, stay locked. Submission, spending and sealed data still require separate permission.

## Minimum publication target: JCR Q2+ potential (not acceptance)

- A paper-oriented research project meets its **research success goal** only when its evidence credibly supports **submission competitiveness for a relevant JCR Q2 or Q1 journal**; **Q1 is preferred where scientifically feasible**, but actual publication, acceptance or favorable review is **not required and cannot be promised**. A positive Run, small incremental publication opportunity, `DRAFTABLE`, self-rated S/A/B/C or an unverified journal quartile never establishes this result.
- Maintain **narrative judgment only**, not new CLI states: `Q2_POTENTIAL_SUPPORTED` (scientific contribution and validation plus a named, source/year/category-verified Q1/Q2 venue with comparable recent papers); `Q2_UPGRADE_POSSIBLE` (bounded falsifiable improvement is plausible); `Q2_UNCERTAIN` (missing decisive original paper/evidence/quartile); `BELOW_Q2_TARGET` (important gap is unsupported and sensible upgrades exhausted). Unknown and early negative Pilot are **not automatic failure**. Keep validated negative/engineering results even if the publication goal is not met.
- Favor the smallest credible evidence path to Q2; when justified, pursue a stronger scientific claim or Q1 fit with proportionate additional tests, not cosmetic neural nets, arbitrary dataset counts or a fixed impact-factor threshold. Never downgrade to a Q3/Q4-only outlet and call the project successful. Per-journal verification: `JCR_EDITION | CATEGORY | QUARTILE | INDEX | SOURCE+DATE | RECENT_COMPARABLE_ARTICLES`. JCR, CAS and SJR quartiles are distinct; no acceptance probability follows from them.
- **PD-RW is authoritative** for journal/Claim assessment when connected: [Q2 goal](https://github.com/phr-devil/Problem-Data-Research-Workflow/blob/main/Q2_PUBLICATION_GOAL.md) / [venue policy](https://github.com/phr-devil/Problem-Data-Research-Workflow/blob/main/VENUE_STRATEGY.md). Forge provides auditable Run/experiment evidence and reports limitations, not autonomous publication certification. `Q2_POTENTIAL_SUPPORTED` must not override the [manuscript writing lock](#manuscript-writing-lock-highest-priority-no-automatic-unlock).

**Scientific controller vs experiment-action adapter**: only PD-RW/user selects the scientific Task and Q2 target; `adapters.opportunity_review` cannot select research problems from across hypotheses based on cheap Probe order. If no prior scientific selection is provided, its `recommended` remains null. The optional [science handoff](../adapters/science_handoff.py) validates local DEV/public SHA references, not the scientific content or original user authorization. Separate [metric handoff](../adapters/pd_rw_bridge.py) validates raw DEV arithmetic, not novelty/causal claims.

**High-value scientific design (existing Skills only):** when choosing a new problem, main dataset, scientific Task or expensive model mechanism, consult [HIGH_VALUE_RESEARCH_ENGINEERING.md](HIGH_VALUE_RESEARCH_ENGINEERING.md) **only as needed**. Key principles: important unanswered knowledge before easy scores, data factors can be observationally confounded, competing explanations need distinct predictions, high-upside mechanisms merit one fair authorized probe, and existing valid Champion is never discarded to force novelty. No extra gate, automatic multi-Agent tree search, journal-scoring model, hidden training/confirmation authorization or manuscript writing.

## Scope and context
- Start from the current **blocker**, not stage 01. Read `AGENTS.md`, the actual project `STATE.json`, relevant source/Run receipts, and **one** Skill. Load other files only to resolve a named dependency.
- Prefer `python -m core.cli brief --dir PROJECT` for a compact project snapshot. It reports pointers, **not** scientific verification. Reuse prior valid experiments, data audits, downloads, code and paper evidence; invalidate stale versions rather than recomputing everything.
- State uncertainties as UNKNOWN, not automatic STOP. An exploration Pilot may be negative without falsifying the Task. Distinguish code error, invalid evaluation, weak mechanism, infeasible Task and unsupported Claim.

**External large-model execution:** read [EXTERNAL_MODEL_EVIDENCE.md](EXTERNAL_MODEL_EVIDENCE.md) only when built-in CPU/DEV bounds are insufficient. External Codex/WorkBuddy training requires its own verified user permission. The streamed output hash preflight does not validate metrics, data provenance or paper novelty; preserve `REPORTED` vs independently recomputed distinctions. No automatic training or sealed access.

## Evidence-first experiment priority (not an extra gate)
- Starting from the current Task/Run, prefer this **skippable** order: legal truth/group/time/inputs → validated simple reference (existing if possible) → observed signal and recoverable error → smallest discriminator or correction → more complex architecture only when it addresses a named unresolved limit, distinct falsifiable mechanism or real deployment need. Some physical/temporal tasks can require complex models from the outset; justify this with a cheap probe where possible.
- Keep three outcomes separate: `LEGAL_SIGNAL`, `MINIMUM_RELIABLE_RESULT`, `MINIMUM_INDEPENDENT_CLAIM`. Simple improvement is not novelty, Oracle headroom is not identifiable deployable gain, negative challenger does not invalidate a preserved reference or Task.
- For experimental cost choose A (read-only existing predictions/statistics), B (authorized lightweight fit), C (authorized complex training). Use the least costly experiment that can change the current decision; these are cost descriptions, not universal GPU/time thresholds or new authorization.
- Preserve the simplest credible matched-information reference, its raw predictions and receipts when testing challengers. Mark incompatible Task/K/evaluator comparisons NOT_COMPARABLE; never silently overwrite old results. On matched simple-baseline domination without a distinct lever, stop *that mechanism* and return the scientific question/novelty gap to PD-RW if used.

## Claim-proportional publication evidence (not a new gate)
- A single real incremental contribution can justify a paper candidate: task-relevant improvement, efficiency/calibration cost for an acceptable accuracy tradeoff, reliable failure/robustness law, or meaningful combination/protocol improvement. Global SOTA, all metrics positive, novel backbone and mandatory multi-dataset superiority are **not** prerequisites.
- Compare with the **strongest relevant matched** simple alternative and named nearest predecessors, not every model ever published. Report adverse metrics and compute/label costs, independent groups, selection history, uncertainty, and a confirmation scope matching the Claim. A single dataset may suffice for a properly limited Claim with genuinely independent confirmation groups; cross-dataset claims require corresponding evidence.
- Separate `ENGINEERING_ASSET_ONLY`, `PAPER_PATH_CANDIDATE`, and `CONFIRMED_CLAIM` as **scientific interpretations already used by PD-RW**, not new Forge CLI enum values. Small DEV gains are exploratory until verified; negative results require a reproducible, not-yet-known insight rather than merely losing a leaderboard.

## Small-discovery rescue and venue handoff (optional)
- At a **real negative or narrow positive** DEV result, distinguish failed algorithm mechanism from viable scientific contribution. Before project-level abandonment, check *once at the affected decision boundary* for a testable new calibration-cost curve, resource–accuracy tradeoff, controlled failure/heterogeneity law, or claim-limited improvement not already resolved by named neighbors. A weak finding is `UNKNOWN/CLAIM_WITH_GAPS` until evidenced, not instantly `NO_INDEPENDENT_CLAIM` or `CONFIRMED`. Do not endlessly retell the same negative score as a novel discovery.
- Pass `CLAIM_SENTENCE | EVIDENCE_RUN | NEAREST_NEIGHBOR_GAP | ONE_DECISIVE_MISSING_TEST | LIMITS` to the research controller when publication assessment is relevant; do not spawn venue search automatically on every Run. The optional S/A/B/C manuscript-potential and STRETCH/TARGET/FALLBACK venue suggestions are **separate, nonbinding advisory axes**, owned by PD-RW if used, not new Forge enum/state gates; C is **not** an automatic scientific failure or Q2 success; S/A is not an evidence badge. Q2 potential is a separate evidence/venue judgment.
- Real venue recommendations require current evidence on scope, article type, recent precedents, indexing/JCR category-year, fees and publisher; do not infer acceptance chances, equate journal quartiles to manuscript potential, or require multi-dataset supremacy. See [PD-RW venue strategy](https://github.com/phr-devil/Problem-Data-Research-Workflow/blob/main/VENUE_STRATEGY.md) only when requested.

## Scientific evidence completion is the primary decision objective (v0.15)
- At the first credible DEV result, a meaningful negative Pilot, and before expensive new architectures or a Task HOLD/PIVOT, assess *once per changed Claim* whether a **small independent contribution** can be completed as an evidence package competitive with a relevant JCR Q2+ journal. A defensible simple improvement, reliable scoped limitation, cost/label saving or meaningful recombination is enough to investigate; it need not be SOTA or a brand-new mechanism.
- Prefer `ONE_CLAIM | NEAREST_NAMED_GAP | CORE_RESULT_RUN | FAIR_COMPARATOR | REQUIRED_GAPS(1..3) | NEXT_LOWEST_COST_PAPER_TEST` to another broad model search when the core paper is feasible. The next action should improve **submission readiness**: fair direct comparison, independent-group effect, claim-matched confirmation, real resource/label cost, or missing scientific evidence, not manuscript-section drafting. Additional models/multi-dataset experiments only when needed to support the chosen Claim, materially improve suitable venue fit with justifiable cost, or requested by the user.
- Lightweight discovery may compare 1–3 **published and task-relevant analogous papers** to learn realistic paper formats and core evidence; this is not full-text novelty certification or a compulsory early journal ranking. PD-RW owns any optional S/A/B/C potential and journal selection. Preserve truthful negatives, actual user authorization, untouched confirmation, uncertainty and nearest-paper distinctions; `DRAFTABLE` is not `SUBMISSION_CANDIDATE`.

## Post-algorithm scientific upgrade (optional, no eighth Skill)

- When a verified algorithm/Champion is already stable, or before an expensive replacement or Task HOLD, use [POST_ALGORITHM_SCIENCE_AUDIT.md](POST_ALGORITHM_SCIENCE_AUDIT.md) **only when relevant new Claim/value questions exist**. Reuse Run/splits/strong simple references; test whether a small change can produce novel, falsifiable scientific knowledge rather than just a DEV score. Never force this at every Run.
- Prefer A) read-only group-paired residual/shift/label and nearest-work analysis; then, only with existing real permission and a distinct predicted signature, B) one minimal fair DEV ablation, intervention, real constraint/cost test; only with separate approval C) claim-frozen independent confirmation. Preserve original Champion and negative evidence; post-hoc slices are exploratory, attribution is not causality.
- Use four narrative decisions (not new CLI states): `UPGRADE_PILOT`, `EVIDENCE_ONLY`, `KEEP_ORIGINAL`, `UNKNOWN`. A weak Claim, unacceptable new compute, missing validation, or nearest-paper coverage should **not** trigger a new architecture. Freeze useful results and hand off a research-results summary, never manuscript prose without the writing lock prerequisites.

## Autonomous work and cost
- Choose the **largest coherent authorized batch**: inspect → implement → directed test → repair → save evidence → decide. Do not stop after every small step or repeatedly ask for already supplied details.
- Match work to its expected information gain. Use a minimal informative baseline/probe first; increase GPU/iterations/review depth only when results may change a scientific decision. Reuse cached results and limit redundant Agent reviews; do not mandate multi-Agent voting.
- Track measured resources when available (elapsed time, GPU, API/Token usage). **Never invent Token or compute costs** from an absent log. Total research value matters more than apparent task-count efficiency.
- During development, run focused tests for affected code and relevant interfaces. Run full CI at integration/release or when a shared invariant changed; preserve safety-critical tests regardless of cost. Avoid repeating unchanged tests without a concrete reason.

## Outputs and visuals
- **No automatic plots, polished figures, slide decks, decorative diagrams, or publication formatting** during exploratory work. Make a minimal diagnostic figure only if it tests a hypothesis or changes the decision. Publication-quality figures follow accepted, verified results.
- Do not generate a Markdown report after every command or Skill. Preserve raw logs/artifacts where they are produced. Default human-facing update is **delta-only**: `RESULT` (new fact), `EVIDENCE` (file/run), `DECISION`, `NEXT`; add `BLOCKER` / `COST` only if material and known. No duplicate narrative, pasted logs, or fake completion estimates.
- Longer summaries are reserved for real decision boundaries, recovery, handoff or final scientific evidence; document only what cannot be reconstructed from code, source and receipts.

## Scientific and permission gates (never optimized away)
- Protect legitimate labels, group splits, legal inference inputs, evaluator/Task versions and untouched independent confirmation. Keep negative Runs and selection history. Strong/fair baselines and evidence-backed novelty remain required for formal Claims.
- First negative Pilot ≠ project STOP. Repair bounded engineering faults automatically inside actual authorization. Continue only with a discriminating mechanism test; pivot when the Task premise fails; avoid infinite no-information tweaking.
- Downloading, installation, CPU/GPU fitting, spending, external transfer, sealed confirmation, submissions and substantive scope changes require actual user authorization. Neither a stored reference, tool parameter nor upstream Skill grants permission.

**Engineering progress test (not the project publication-success test):** valid evidence and reproducible progress per total real resource cost, not report length, number of Agent calls, figures or procedural checkmarks.

**v0.7 non-negotiable:** independent DEV metric recomputation and event-chain verification are required before claiming a model score or selecting Champion. Never attempt to use a normal development event as sealed confirmation; use a separately authorized evaluator when available. Statistics support uncertainty analysis but must not impose a universal p-value gate on exploratory research.
